# ADR 0003: Владение состоянием боя (Battle State Ownership)

## Контекст (Context)

В архитектуре присутствует Angular (с NgRx SignalStore) для UI/кэширования и независимый изоморфный `Battle Engine` для логики боя. Возникает вопрос: где хранится мутабельное состояние самого боя (HP покемонов, активные статусы, очередность ходов)?

## Решение (Decision)

1.  **Движок — Источник Правды:** `Battle Engine` является инкапсулированным конечным автоматом (State Machine) и единственным владельцем текущего состояния боя (`BattleState`).
2.  **Отвязка от NgRx:** Мутабельное состояние боя **не** хранится в NgRx. NgRx SignalStore используется исключительно для статического кэша (каталог покемонов, список команд).
3.  **Экспорт Состояния:** Движок экспортирует свое актуальное состояние наружу (вероятно, оборачивая его в Сигнал или предоставляя метод `getState()`), чтобы Angular мог реактивно обновлять UI (полоски здоровья, кнопки).

## Последствия (Consequences)

- **Плюс:** 100% совместимость с PartyKit. Сервер PartyKit просто создаст инстанс `BattleEngine` в памяти и будет держать его стейт, принимая WebSocket-команды от клиентов.
- **Плюс:** Четкое разделение ответственности. UI не может случайно или нелегально изменить HP покемона напрямую, он может только отправить `Command`.
- **Минус:** Angular-компонентам нужно подписываться на обновления из вне-Angular источника (Engine), что требует аккуратной работы с Сигналами для триггера обновлений без zone.js.
