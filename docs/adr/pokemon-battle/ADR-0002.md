# ADR 0002: Управление данными PokeAPI и маппинг для Battle Engine

## Контекст (Context)

Боевой движок (`Battle Engine`) нуждается в данных о покемонах (статы, способности) для проведения расчетов. PokeAPI предоставляет избыточные данные. Делать HTTP-запросы из самого движка нельзя, так как он должен быть синхронным и независимым от сети (для будущего переноса на PartyKit).

## Решение (Decision)

1.  **Загрузка и Кэширование (Angular):** Данные из PokeAPI загружаются Angular-сервисами частями (пагинация, фильтры, по 20 штук) и кэшируются в `NgRx Store`.
2.  **Маппинг (DTO):** Перед передачей в `Battle Engine`, сырые данные из PokeAPI мапятся в строгие, минималистичные интерфейсы нашего домена (например, `BattlePokemon`, `BattleMove`), содержащие только то, что нужно для боя (статы на 50 уровне, ID спрайтов).
3.  **Синхронная Инициализация:** При старте боя Angular извлекает нужные слепки (`Snapshot`) из NgRx Store и передает их в `Battle Engine` синхронно (`BattleEngine.init(teams)`). Движок работает исключительно с локальными, подготовленными данными.

## Последствия (Consequences)

- **Плюс:** `Battle Engine` остается чистым, быстрым и синхронным.
- **Плюс:** Экономия трафика и отсутствие дублирующих запросов благодаря кэшированию в NgRx.
- **Минус:** Необходимость поддерживать мапперы (Data Transfer Objects) между ответами PokeAPI и доменной моделью движка.
