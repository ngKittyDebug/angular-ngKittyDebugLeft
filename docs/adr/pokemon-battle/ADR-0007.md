# ADR 0007: Управление очередью анимаций (Animation Event Queue)

## Контекст (Context)

Боевой движок синхронно вычисляет исход хода и генерирует массив событий (`Event[]`). Эти события необходимо последовательно анимировать. Возникает вопрос: кто управляет таймингами и переключениями между анимациями — Angular или сам слой Canvas?

## Решение (Decision)

1.  **Canvas Renderer как Менеджер:** Angular передает сгенерированный массив событий целиком в независимый класс `CanvasRenderer`.
2.  **Изолированный Game Loop:** `CanvasRenderer` самостоятельно управляет очередью (Animation Queue) внутри своего цикла `requestAnimationFrame`. Он проигрывает анимацию для текущего события, дожидается её завершения (по кадрам или времени) и переходит к следующему.
3.  **Обратный вызов (Callback/Event):** Только когда `CanvasRenderer` опустошает очередь, он уведомляет Angular (например, через Observable или изменение Сигнала), что анимации завершены, и UI может разблокировать кнопки для следующей фазы выбора.

## Последствия (Consequences)

- **Плюс:** Максимальная производительность. Тайминги анимаций не связаны с Change Detection в Angular.
- **Плюс:** Чистое разделение ответственности. Angular не знает, сколько длится анимация огнемета.
- **Минус:** Сложность в самом `CanvasRenderer` — нужно написать менеджер состояний для анимаций (State Machine для визуальной части).
