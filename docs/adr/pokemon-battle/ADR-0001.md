# ADR 0001: Изолированный изоморфный Battle Engine и Zoneless Rendering

## Контекст (Context)

В проекте разрабатывается фича "Битва Покемонов". Планируется два режима: игра против скриптованного ИИ (локально) и мультиплеер (в будущем, через PartyKit). Отрисовка боя происходит на Canvas, а UI управления — на Angular. Существует риск того, что 1) логика боя будет жестко связана с Angular, что сделает невозможным её перенос на сервер PartyKit, и 2) 60 FPS цикл Canvas убьет производительность Angular из-за Change Detection.

## Решение (Decision)

1.  **Изоморфный Battle Engine:** Ядро логики боя (расчет урона, состояния, очередности ходов) выносится в отдельный модуль на чистом TypeScript (вероятно, в `shared-game/`). Этот модуль ничего не знает об Angular. Он управляется паттерном Command (принимает действия) и генерирует Events (возвращает результат).
2.  **Zoneless и Сигналы:** Мы используем Zoneless подход в Angular. Цикл `requestAnimationFrame` для Canvas работает без Zone.js (напрямую).
3.  **Агрегация состояний:** Angular отвечает только за хранение состояния в Сигналах, отрисовку кнопок/меню (UI) и перехват пользовательского ввода (Command) для передачи в Battle Engine.

## Последствия (Consequences)

- **Плюс:** Легкий переход на PartyKit. Движок просто запускается на сервере, а клиентский Angular-код только шлет команды и рисует события по сети.
- **Плюс:** Отличная производительность UI, так как Canvas не спамит Change Detection.
- **Минус:** Усложнение архитектуры на раннем этапе (строгое разделение UI и логики). Необходимо спроектировать надежную шину событий между Engine и Canvas.
