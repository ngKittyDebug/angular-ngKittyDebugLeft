# ADR 0009: Механика урона и способностей (Damage & Moves)

## Контекст (Context)

Необходимо определить степень достоверности механик боя покемонов (формула урона, статусные эффекты, логика способностей). Оригинальная механика сложна и требует большого объема данных (матрицы типов) и уникального кода для сотен способностей.

## Решение (Decision)

1.  **Упрощенная формула урона:** Для MVP используется упрощенная математическая модель урона: `(Power * (Attack / Defense)) * TypeMultiplier * STAB`. Сложные механики (Crit, Random Roll 0.85-1.0, Stages -6..+6) могут быть добавлены позже или упрощены.
2.  **Матрица типов (Type Chart):** Таблица эффективности типов (Water бьет Fire на x2) хардкодится локально в константах движка, чтобы не делать лишних сложных запросов и парсинга из PokeAPI.
3.  **Хардкод Способностей в Движке:** Бизнес-логика эффектов (например, "10% шанс паралича") не парсится из описаний PokeAPI. Вместо этого в `Battle Engine` создается набор паттернов или стратегий (например, `DamageEffect`, `StatusEffect`, `StatChangeEffect`). При загрузке данных из PokeAPI, DTO-маппер "собирает" нужный класс атаки, подставляя туда константы (power=90) и привязывая нужный хардкодный эффект из библиотеки движка.

## Последствия (Consequences)

- **Плюс:** Быстрый старт и предсказуемое поведение движка. Нет магии с парсингом текста.
- **Минус:** Невозможность поддержать все 800+ атак из коробки. Разработчикам придется вручную программировать сложные атаки (например, _Protect_ или _Solar Beam_) в коде движка.
