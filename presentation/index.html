Решение 1 · Два подхода к формам

осознанный выбор, задокументированный в AGENTS.md — чтобы AI не переписывал «как надо»

✅ Выбрали

Смешанная парадигма
  • login-form → Reactive Forms
  • signup-form → Signal Forms (Angular 22)
  • Обе реализации живут рядом как учебный пример
vs

❌ Альтернатива

Один API везде
  • Только Reactive Forms — стабильно
  • Или только Signal Forms — современно
  • Меньше сюрпризов при поддержке
Почему так: намеренный выбор — учебный пример обоих API рядом. Задокументирован в AGENTS.md как accepted trade-off, не tech debt — иначе каждый следующий разработчик (и каждый AI-агент) будет «починять» это как баг. — и да, Клавдий действительно пытался это «починить». Один раз

Решение 2 · Transloco: директива, не пайп

спойлер: пайп тоже работает, но хуже

✅ Выбрали

*transloco директива
  • Одна подписка на компонент
  • Встроенный кеш и ленивая загрузка по скоупу
  • t('key', params) — явно, без pipe-chain
vs

❌ Альтернатива

| transloco pipe
  • Пере-вычисляется на каждый CD цикл
  • Нет встроенного кеша
  • Чуть понятнее для новичков — и только

Бонус-факт: 583 ключа перевода × 2 языка. Если бы мы выбрали pipe — Angular CD при смене языка прошёлся бы по всем 583 ключам на каждом цикле. Директива считает один раз. Математика на нашей стороне.

Решение 3 · Фильтры там, где данные

или: что делать, когда API не умеет фильтровать

✅ Выбрали

Один запрос + computed() на фронте
  • Загружаем всех 1300+ покемонов один раз
  • Фильтры — пересечения массивов через computed()
  • Debounce + resource(): UI отзывчивый, запросов минимум
vs

❌ Альтернатива

Прокси-бэкенд с фильтрацией
  • Свой сервер, который проксирует и фильтрует PokeAPI
  • N запросов при каждом изменении фильтра
  • Сложность выросла бы раза в три — ради той же цели
«Дёшево и сердито» — 1300+ покемонов влезают в память, пересечения считаются мгновенно, бэкенд не нужен. Алексей придумал, все согласились. — спринт 2, раздел «пагинация и поиск»

История провала · Signal Forms + Taiga UI

реальная, незалакированная, с хеппи-эндом средней степени счастья

💥
Что сломалось Форма регистрации — Signal Forms (Angular 22). Taiga UI читает control.touched для показа ошибок. Проблема: с Signal Forms markAsTouched() не распространяется правильно — ошибки валидации появлялись сразу при загрузке страницы, на пустых нетронутых полях.
🔧
Что пробовали Стандартные touched/invalid-гарды на полях. Разные Taiga-валидаторы. Полдня чтения документации Taiga UI (спойлер: Signal Forms там не упоминаются вообще). Клавдий предлагал варианты, мы их отклоняли.
🏳️
Чем закончилось Ручной флаг firstSubmit + вызов validate() в обработчике сабмита. Работает. Не элегантно. Но работает — и это задокументировано в AGENTS.md, чтобы следующий разработчик не прошёл тот же путь.
«Не используй новую фичу фреймворка, если её не поддерживает твоя UI-библиотека.» — наш вывод, выбитый в камне. Или хотя бы в AGENTS.md
