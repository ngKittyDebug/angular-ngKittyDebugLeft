DI — иерархия инжекторов

Injector Hierarchy, environment vs element injectors, tree-shaking.

1. Как работает иерархия инжекторов

Когда компонент запрашивает зависимость через inject(Service), Angular ищет её снизу вверх по цепочке инжекторов.

Поиск ↑
Element Injector providers в @Component/@Directive текущего элемента
Parent Element Injectors providers предков по дереву компонентов
Environment Injector Lazy route providers, NgModule providers
Root Injector providedIn: 'root', app.config.ts providers
Platform Injector Общий для нескольких Angular-приложений на странице

Если не найдено ни на одном уровне — ошибка NullInjectorError.

2. Ограничение области сервиса — providers в компоненте

@Component({
  selector: 'left-paw-wizard',
  providers: [WizardStateService], // свой экземпляр для этого компонента
})
export class WizardComponent {
  private state = inject(WizardStateService); // получает изолированный экземпляр
}

@Component({ selector: 'left-paw-step-one' })
export class StepOneComponent {
  // Ищет у родителей → найдёт в WizardComponent
  private state = inject(WizardStateService);
}
Паттерн изолированного состояния

Регистрируй сервис в корневом компоненте фичи — все дочерние компоненты получат тот же экземпляр, изолированный от остального приложения. При уничтожении компонента сервис тоже уничтожается — нет утечек.

3. Environment vs Element Injectors

Environment Injector Element Injector
Root, Platform, Lazy route @Component providers, @Directive providers
Не привязан к дереву компонентов Существует пока жив компонент
EnvironmentInjector — инжектируемый Injector — текущий element injector

4. Tree-shaking: providedIn: 'root' vs providers: []

// Tree-shakeable: если сервис не инжектируется — не попадёт в бандл
@Injectable({ providedIn: 'root' })
export class AnalyticsService { }

// Не tree-shakeable: явная регистрация всегда включает в бандл
@NgModule({
  providers: [AnalyticsService], // всегда в бандле даже если не используется
})
Ловушка на интервью

providedIn: 'root' — tree-shakeable: если ни один компонент не инжектирует сервис, esbuild/webpack удаляет его из бандла. Регистрация в providers: [] NgModule — не tree-shakeable, включается всегда.

Проверь себя

Retrieval practice — не подглядывай в текст выше. Выбери один вариант.

1. Компонент запрашивает MyService. Где Angular ищет его первым?

2. Что происходит, если зависимость не найдена ни в одном инжекторе?

3. Сервис в providers: [] компонента — получат ли его дочерние компоненты?

4. Почему providedIn: 'root' поддерживает tree-shaking, а NgModule.providers — нет?
