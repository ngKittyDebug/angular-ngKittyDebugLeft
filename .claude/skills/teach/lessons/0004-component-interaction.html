Урок 4 из серии «Angular Interview Prep»

Взаимодействие компонентов

input(), output(), model(), shared service — и когда что выбрать.

1. input() — данные от родителя к дочернему

// child.component.ts
export class ChildComponent {
  name = input<string>();           // опциональный, тип string | undefined
  count = input.required<number>(); // обязательный, ошибка если не передан
  label = input('Default');         // с дефолтным значением
}

// parent.component.html
<app-child [name]="userName" [count]="42" />
Формула ответа

input() возвращает Signal — в шаблоне читается как {{ name() }}, в TS как this.name(). Это важно — не как обычное свойство.

2. output() — события от дочернего к родителю

// child.component.ts
export class ChildComponent {
  saved = output<string>(); // эмитит string

  onSave() {
    this.saved.emit('данные');
  }
}

// parent.component.html
<app-child (saved)="handleSave($event)" />

output() — не Signal, это OutputEmitterRef. Вызывается через .emit(). В шаблоне родителя биндится через (eventName).

3. model() — двусторонняя привязка

// child.component.ts
export class ChildComponent {
  value = model<string>(''); // readable + writable signal

  clear() { this.value.set(''); } // изменяет и эмитит наружу
}

// parent.component.html
<app-child [(value)]="parentValue" />
Когда использовать model()

Когда дочерний компонент и читает, и изменяет значение — например, поле ввода или переключатель. Это заменяет связку input() + output() с событием valueChange.

4. Shared Service

@Injectable({ providedIn: 'root' })
export class CartService {
  private items = signal<Item[]>([]);
  readonly items$ = this.items.asReadonly();

  add(item: Item) { this.items.update(list => [...list, item]); }
}

// в любом компоненте:
export class ProductComponent {
  private cart = inject(CartService);
  add() { this.cart.add(this.product()); }
}

Сервис — синглтон: один экземпляр на всё приложение (при providedIn: 'root'). Идеально для sibling-компонентов или компонентов далеко по дереву.

5. input()/output() vs сервис — когда что?

Ситуация Выбор
Родитель передаёт данные дочернему input()
Дочерний сообщает родителю о событии output()
Sibling, несвязанные по дереву Shared service
Сложное глобальное состояние NgRx SignalStore
Дочерний и читает, и изменяет значение model()

6. input()/output() vs @Input()/@Output()

Новый API (Signals) Устаревший (@Input/@Output)
input() → Signal @Input() → обычное свойство
Читается через this.name() Читается через this.name
output() → OutputEmitterRef @Output() → EventEmitter
Интегрирован с change detection сигналов Триггерит ngOnChanges
Ловушка на интервью

input() возвращает Signal, поэтому ngOnChanges на него не вызывается. Для реакции на изменение input-сигнала используй effect() или computed().
