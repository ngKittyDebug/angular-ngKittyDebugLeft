exhaustMap vs concatMap

Оба оператора защищают от гонки запросов — но по-разному.

Общий контекст

Когда источник Observable эмитит значение, а предыдущий «внутренний» Observable ещё не завершился, у нас возникает конфликт. Разные операторы решают его по-разному:

Оператор Что делает с новым значением, пока идёт предыдущий запрос
switchMap Отменяет предыдущий, запускает новый
exhaustMap Игнорирует новое — предыдущий продолжает работать
concatMap Ставит в очередь — запустит после завершения предыдущего
mergeMap Запускает параллельно — не ждёт никого

exhaustMap — «Занято, перезвоните позже»

Представь кнопку «Сохранить». Пользователь кликает дважды. exhaustMap обрабатывает первый клик, второй выбрасывает. Когда первый запрос завершится — оператор снова готов принять следующий.

Мраморная диаграмма:

клики:
1 2 3
запросы:
1 ×2 игнор 3

Клик 2 пришёл пока выполнялся запрос 1 — он отброшен навсегда.

Ключевое

exhaustMap теряет промежуточные события. Это сознательно — нам не важно, сколько раз пользователь нажал «Удалить аккаунт» пока идёт первый запрос.

В твоём коде

// profile.store.ts — updateProfile
updateProfile: rxMethod<UpdateUserModel>(
  pipe(
    tap(() => patchState(store, { isLoading: true })),
    exhaustMap((dto) =>           // <-- если пользователь кликнул "Сохранить" дважды —
      api.updateUser(dto).pipe(   //     второй клик игнорируется
        tap(...)
      )
    ),
  ),
),

Так же используется для deleteAccount и changePassword — там тоже недопустимо дублировать запрос.

concatMap — «Стань в очередь»

Представь что пользователь быстро добавил покемона в избранное, потом убрал. Нам важно что оба запроса выполнятся, и в правильном порядке. concatMap ставит второй запрос в очередь и ждёт завершения первого.

Мраморная диаграмма:

события:
+ –
запросы:
+ ждёт... –

Минус пришёл пока выполнялся плюс — он поставлен в очередь, не потерян.

Ключевое

concatMap не теряет ни одно событие. Все запросы выполнятся последовательно в том порядке, в котором пришли.

В твоём коде

// profile.store.ts — addToFavorites
addToFavorites: rxMethod<string>(
  pipe(
    tap(() => patchState(store, { isLoading: true })),
    concatMap((pokemonName) =>         // <-- быстрое "добавить + убрать":
      api.addFavorite(pokemonName).pipe(//     оба запроса выполнятся по очереди
        tap(...)
      )
    ),
  ),
),

Как их различить на собеседовании

Задай себе один вопрос:
«Важно ли мне, что произойдёт с этим событием, пока идёт предыдущий запрос?»

— Нет, потеря допустима → exhaustMap
— Да, нельзя терять → concatMap

Проверь себя

1. Пользователь трижды быстро кликает «Удалить аккаунт». Какой оператор правильный?

2. Пользователь быстро добавил в избранное «Pikachu», потом убрал. Итого 2 запроса. Важно что оба выполнятся и в правильном порядке. Какой оператор?
