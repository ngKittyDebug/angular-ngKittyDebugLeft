Урок 12 из серии «Angular Interview Prep»

Dependency Injection — базовый

inject(), providedIn, standalone DI, ViewChild.

1. Что такое Dependency Injection?

DI — паттерн, при котором объект получает свои зависимости извне, а не создаёт их сам. Angular-инжектор хранит экземпляры сервисов и передаёт их компонентам при запросе.

Зачем DI?

Тестируемость (можно подменить зависимость моком), переиспользование (сервис создаётся один раз), слабая связанность (компонент не знает, как создаётся сервис).

2. Создание сервиса и inject()

@Injectable({ providedIn: 'root' })
export class UserService {
  private http = inject(HttpClient);

  getUser(id: string) {
    return this.http.get<User>(`/api/users/${id}`);
  }
}

// В компоненте:
export class ProfileComponent {
  private userService = inject(UserService); // modern API
  // или через конструктор (устаревший способ, но валиден):
  // constructor(private userService: UserService) {}
}

3. providedIn: 'root' vs 'any' vs providers в компоненте

Способ Область действия Когда
providedIn: 'root' Всё приложение, синглтон Глобальные сервисы (AuthService, ThemeService)
providedIn: 'any' Каждый lazy-модуль свой экземпляр Сервис с состоянием для lazy-feature
providers: [] в @Component Только этот компонент + потомки Изолировать сервис для одной части UI
Ловушка на интервью

Сервис в providers: [] компонента — новый экземпляр для каждого экземпляра компонента, не синглтон. При уничтожении компонента — сервис тоже уничтожается.

4. DI в standalone компонентах

// В маршруте — для lazy feature:
{
  path: 'profile',
  providers: [ProfileService], // доступен только этой фиче
  loadComponent: () => import('./profile.component'),
}

// В компоненте:
@Component({
  providers: [LocalDialogService], // только для этого компонента
})
export class ProfileComponent {
  private dialog = inject(LocalDialogService);
}

5. ViewChild и ViewChildren

@Component({
  template: `
    <input #nameInput />
    <app-card #card />
  `,
})
export class FormComponent {
  // Ссылка на DOM-элемент
  nameInput = viewChild<ElementRef>('nameInput');

  // Ссылка на дочерний компонент
  card = viewChild(CardComponent);

  // Несколько элементов
  items = viewChildren(ItemComponent);

  ngAfterViewInit() {
    this.nameInput()?.nativeElement.focus();
  }
}
Формула ответа

viewChild() — Signal API (Angular 17+), доступен сразу как signal. Старый @ViewChild() — доступен только после ngAfterViewInit. viewChildren() возвращает Signal<ReadonlyArray<T>>.
