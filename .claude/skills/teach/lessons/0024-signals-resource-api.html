Signals — Resource API

resource() и rxResource() — асинхронная загрузка данных на Signals.

1. Проблема без Resource API

Традиционный подход — подписка на Observable + ручное управление состоянием: 

// Старый способ — много бойлерплейта
export class PokemonComponent {
  private pokemonService = inject(PokemonService);

  protected pokemon = signal<Pokemon | null>(null);
  protected isLoading = signal(false);
  protected error = signal<string | null>(null);
  protected id = input.required<number>();

  constructor() {
    effect(() => {
      const id = this.id();
      this.isLoading.set(true);
      this.error.set(null);

      this.pokemonService.getById(id)
        .pipe(takeUntilDestroyed())
        .subscribe({
          next: p => { this.pokemon.set(p); this.isLoading.set(false); },
          error: e => { this.error.set(e.message); this.isLoading.set(false); },
        });
    });
  }
}

2. resource() — нативный async API

resource() (Angular 19+, stable) — декларативный способ загрузить данные асинхронно, реагирующий на изменения сигналов-параметров. 

import { resource } from '@angular/core';

export class PokemonComponent {
  protected id = input.required<number>();

  // resource() автоматически:
  // - перезапускает запрос при изменении id()
  // - отменяет предыдущий запрос при новом
  // - отслеживает loading/error состояния
  protected pokemonResource = resource({
    request: () => this.id(),      // параметр — Signal
    loader: ({ request: id }) =>
      fetch(`/api/pokemon/${id}`).then(r => r.json()), // → Promise
  });

  // Доступные сигналы:
  // pokemonResource.value()    — Signal<Pokemon | undefined>
  // pokemonResource.isLoading() — Signal<boolean>
  // pokemonResource.error()    — Signal<unknown>
  // pokemonResource.status()   — Signal<ResourceStatus>
}
<!-- В шаблоне: -->
@if (pokemonResource.isLoading()) {
  <p>Загрузка...</p>
} @else if (pokemonResource.error()) {
  <p>Ошибка: {{ pokemonResource.error() }}</p>
} @else {
  <h1>{{ pokemonResource.value()?.name }}</h1>
}

3. rxResource() — для Observable

import { rxResource } from '@angular/core/rxjs-interop';

export class PokemonComponent {
  protected id = input.required<number>();
  private pokemonService = inject(PokemonService);

  protected pokemonResource = rxResource({
    request: () => this.id(),
    loader: ({ request: id }) =>
      this.pokemonService.getById(id), // → Observable
  });
}
resource() rxResource()
loader возвращает Promise loader возвращает Observable
Нет зависимости от RxJS Требует @angular/core/rxjs-interop
Подходит для fetch API Подходит для HttpClient (возвращает Observable)

4. Дополнительные возможности Resource

// Ручное обновление (refresh):
pokemonResource.reload();

// Локальная запись (optimistic update):
pokemonResource.set({ ...pokemonResource.value()!, hp: 100 });

// Статусы:
// ResourceStatus.Idle      — запрос не был сделан
// ResourceStatus.Loading   — запрос в процессе
// ResourceStatus.Resolved  — успех
// ResourceStatus.Error     — ошибка
// ResourceStatus.Reloading — перезагрузка

Зачем Resource API? Заменяет паттерн «signal + effect + subscribe + loading/error флаги» одной декларацией. Автоматически отменяет предыдущие запросы при изменении параметров. Полностью интегрирован с Angular change detection через Signals.

Ловушка на интервью

resource() вызывает loader только при изменении request — сигнала-параметра. Если request: () => undefined — запрос не отправляется. Это полезно для условной загрузки: request: () => this.userId() || undefined.
