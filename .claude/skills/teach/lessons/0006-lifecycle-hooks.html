Lifecycle Hooks

Порядок хуков, ngOnInit vs конструктор, ngOnDestroy, afterNextRender.

1. Что такое lifecycle hooks?

Angular вызывает хуки жизненного цикла в определённые моменты существования компонента — создание, обновление входных данных, рендер, уничтожение. Имплементируются через интерфейсы (OnInit, OnDestroy и др.).

2. Порядок вызова

Хук Когда
constructor DI — до инициализации input-ов
ngOnChanges При каждом изменении @Input-ов (до OnInit при первом рендере)
ngOnInit После первой инициализации input-ов (1 раз)
ngDoCheck Каждый цикл change detection
ngAfterContentInit После проецирования ng-content (1 раз)
ngAfterContentChecked После каждой проверки projected content
ngAfterViewInit После первого рендера view + дочерних (1 раз)
ngAfterViewChecked После каждой проверки view
ngOnDestroy Перед удалением компонента из DOM

3. ngOnInit vs конструктор

constructor ngOnInit
Только DI — инжекция зависимостей Логика инициализации с данными
Input-ы ещё не установлены Input-ы уже доступны
Нельзя делать HTTP-запросы Можно подписываться, запрашивать данные 
export class UserComponent implements OnInit {
  private userService = inject(UserService);
  protected user = signal<User | null>(null);

  // DI only
  constructor() {}

  // логика инициализации
  ngOnInit() {
    this.userService.getUser().subscribe(u => this.user.set(u));
  }
}

4. ngOnDestroy — очистка ресурсов

export class TimerComponent implements OnDestroy {
  private subscription = Subscription.EMPTY;

  ngOnInit() {
    this.subscription = interval(1000).subscribe(tick => ...);
  }

  ngOnDestroy() {
    this.subscription.unsubscribe(); // без этого — memory leak
  }
}
Ловушка на интервью

Незакрытые подписки — источник memory leak. В современном Angular используй takeUntilDestroyed() — он автоматически отписывается в ngOnDestroy. Или DestroyRef + inject(DestroyRef).onDestroy().

5. ngOnChanges и SimpleChanges

export class CardComponent implements OnChanges {
  @Input() title = '';

  ngOnChanges(changes: SimpleChanges) {
    if (changes['title']) {
      const { previousValue, currentValue, firstChange } = changes['title'];
      console.log(`${previousValue} → ${currentValue}, first: ${firstChange}`);
    }
  }
}

Важно: ngOnChanges срабатывает только для @Input() (decorator API), не для input() (signal API). При первом рендере вызывается до ngOnInit.

6. afterNextRender и afterEveryRender

export class ChartComponent {
  constructor() {
    // Выполнится один раз после первого рендера в браузере
    afterNextRender(() => {
      this.initChart(); // доступ к DOM безопасен
    });

    // Выполняется после каждого рендера
    afterEveryRender(() => {
      this.updateSize();
    });
  }
}
afterNextRender vs ngAfterViewInit

ngAfterViewInit вызывается и на сервере (SSR) — там DOM нет. afterNextRender — только в браузере, безопаснее для SSR-совместимых приложений. Используй afterNextRender для инициализации DOM-зависимых библиотек.
