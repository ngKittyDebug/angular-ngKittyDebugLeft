Урок 2 из серии «Angular Interview Prep»

Angular: основы и CLI

Блок «Общие вопросы» + «Angular CLI» — 6 вопросов из списка интервью.

1. Что такое Angular?

Формула ответа

Angular — это фреймворк (не библиотека) от Google для создания Single Page Applications на TypeScript. В отличие от React, он opinionated: маршрутизация, DI, HTTP-клиент, формы — всё встроено, а не подбирается самостоятельно.

Ловушка на интервью

Если спросят «чем Angular отличается от React» — не останавливайтесь на «один фреймворк, другой библиотека». Добавьте: Angular навязывает структуру (Dependency Injection, декораторы, NgModule/standalone), React даёт только UI-слой и оставляет выбор архитектуры.

2. Что такое Angular CLI?

Angular CLI — инструмент командной строки, который автоматизирует рутину: создание проекта, генерацию кода, сборку, запуск тестов, линтинг.

Команда Что делает
ng new my-app Создаёт проект: tsconfig, angular.json, src/, git init
ng serve Dev-сервер с hot reload на :4200
ng build Продакшн-сборка в dist/ (esbuild)
ng generate / ng g Генерация компонентов, сервисов, директив…
ng test / ng lint Запуск тестов и линтера

Полезные флаги ng new

ng new my-app \
  --routing          # сразу создаёт RouterModule/app.routes.ts
  --style=scss       # SCSS вместо CSS
  --standalone       # standalone-компоненты (по умолчанию с Angular 17)
  --ssr              # серверный рендеринг (SSR)

3. Генерация компонента

ng generate component features/my-feature/my-widget
# или коротко:
ng g c features/my-feature/my-widget

CLI создаёт .ts, .html, .scss, .spec.ts и обновляет импорты (в standalone-проекте — ничего не трогает в модуле, потому что модулей нет). Другие шорт-коды: ng g s (service), ng g d (directive), ng g p (pipe).

4. Структура проекта: angular.json и app.config.ts

angular.json — конфигурация воркспейса. Описывает projects, build targets, пути к assets и styles, параметры компилятора. Именно здесь указывается, какой сборщик использовать (esbuild / webpack) и где лежат тесты.

app.config.ts — точка конфигурации приложения в standalone-режиме (заменяет NgModule). Здесь регистрируются глобальные провайдеры: provideRouter(routes), provideHttpClient(), provideTaiga(), provideTransloco() и т.д. 

// src/app/app.config.ts
export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter(routes),
    provideHttpClient(),
    provideTransloco({ ... }),
  ],
};

Точка входа — src/main.ts: bootstrapApplication(AppComponent, appConfig).

5. Взаимодействие компонентов

Шесть способов — важно знать все, чтобы выбрать подходящий для сценария:

Способ Когда использовать
input() / output() Родитель → дочерний (input), дочерний → родитель (output)
Shared service Несвязанные компоненты (sibling, далёкие узлы дерева)
viewChild() Родитель вызывает метод/читает свойство дочернего
model() Двусторонняя привязка ([(ngModel)]-аналог для сигналов)
RxJS Subject в сервисе Реактивный поток событий между несвязанными компонентами
NgRx / SignalStore Глобальное состояние, сложные flows, dev tools нужны
