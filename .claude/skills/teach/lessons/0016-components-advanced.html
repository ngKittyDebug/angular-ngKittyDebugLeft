Components — продвинутый

ViewEncapsulation, host, ng-content, ng-template, ngTemplateOutlet, contentChild.

1. ViewEncapsulation

Режим Поведение Когда
Emulated (default) Angular добавляет уникальные атрибуты к селекторам Всегда, кроме исключений
None Стили глобальные, нет изоляции Когда нужны глобальные стили из компонента
ShadowDom Нативный Shadow DOM браузера Web Components, полная изоляция

2. host в @Component

@Component({
  selector: 'left-paw-card',
  host: {
    'class': 'card',              // статический класс
    '[class.active]': 'isActive()', // динамический класс
    '[attr.aria-label]': 'label()', // атрибут
    '(click)': 'onClick()',         // событие
    'role': 'article',              // статический атрибут
  },
})
host vs @HostBinding/@HostListener

Оба делают одно и то же. host: {} — декларативно, всё в одном месте, предпочтительно. @HostBinding/@HostListener — декораторы на методах/свойствах, старый стиль.

3. exportAs и providers в @Component

@Component({
  selector: 'left-paw-modal',
  exportAs: 'modal',            // имя для ссылки в шаблоне
  providers: [ModalService],    // изолированный сервис
})
export class ModalComponent {
  open() { ... }
  close() { ... }
}

// В шаблоне:
<left-paw-modal #myModal="modal" />
<button (click)="myModal.open()">Открыть</button>

4. ng-content — слоты

// card.component.html
<div class="card">
  <ng-content select="[slot=header]" />
  <ng-content />  <!-- дефолтный слот -->
  <ng-content select="[slot=footer]" />
</div>

// использование:
<left-paw-card>
  <h2 slot="header">Заголовок</h2>
  <p>Основной контент</p>
  <button slot="footer">Закрыть</button>
</left-paw-card>

5. ng-template и ngTemplateOutlet

// Определяем шаблон
<ng-template #loadingTpl>
  <div class="spinner">Загрузка...</div>
</ng-template>

// Рендерим через outlet:
<ng-container *ngTemplateOutlet="loadingTpl" />

// С контекстом:
<ng-template #greet let-name="name">
  <p>Привет, {{ name }}</p>
</ng-template>
<ng-container *ngTemplateOutlet="greet; context: { name: 'Оксана' }" />

6. contentChild и contentChildren

// Компонент получает доступ к проецируемому контенту:
@Component({ template: '<ng-content />' })
export class TabGroupComponent {
  // Signal API (Angular 17+):
  activeTab = contentChild(TabComponent);
  allTabs = contentChildren(TabComponent);

  ngAfterContentInit() {
    // contentChild доступен здесь
    console.log(this.activeTab()?.label);
  }
}
ViewChild vs ContentChild

viewChild — для элементов в собственном шаблоне компонента.
contentChild — для элементов, проецируемых через ng-content (приходят от родителя).
